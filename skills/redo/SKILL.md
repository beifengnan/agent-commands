# /redo — 推翻重来，写优雅的方案

适用场景：第一版实现能跑但很别扭，堆了补丁、绕了弯路，或者在做的过程中才搞清楚问题的真正形状。

## 做法

1. 回顾刚才的实现和整个过程：真正的需求是什么，踩了哪些坑，哪些设计是被迫凑出来的。
2. 用两三句话写出新方案的核心思路，说明它比旧方案好在哪里（更少代码、更少特殊情况、更清晰的边界）。用户若附带了要求，一并满足。
3. 撤掉旧实现（只撤这次任务里写的代码，不动无关的改动；不确定时先问）。
4. 从头实现新方案：
   - 优先复用项目里已有的工具和模式
   - 不要为了"优雅"过度抽象，简单直接优先
   - 保持对外行为与需求一致
5. 运行构建和测试，确认新实现通过，并且至少和旧实现一样能工作。

## 报告

- 新旧方案的对比（思路、代码行数、去掉了哪些特殊处理）
- 验证结果
- 仍然存在的取舍或需要用户决定的点
