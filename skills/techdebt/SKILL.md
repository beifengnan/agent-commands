# /techdebt — 收尾时清理技术债

> 来源：Anthropic《Claude Code 高级用户技巧》中，团队推荐的自定义命令示例——在每次会话结束时运行，找出并清理重复代码。

和 `/audit` 的区别：`/audit` 体检整个项目；`/techdebt` 只盯**本次会话 / 当前分支**的改动及其直接相关的代码，适合每次收尾时跑。

## 做法

1. 确定范围：当前分支相对主分支的改动 + 本次会话里改过的文件，以及它们直接调用或被调用的代码。用户若附带了路径，只看该路径。
2. 查找：
   - **重复代码**：新写的逻辑是否与项目中已有的函数、工具、组件重复，或者几处新代码彼此复制粘贴
   - 本次留下的临时代码：调试输出、被注释掉的代码、写死的值、TODO
   - 本次改动后变成死代码的旧实现、不再使用的导入和依赖
   - 为了赶进度写的绕路逻辑、多余的特殊情况处理
3. 有把握的（行为不变、可验证）直接清理：把重复逻辑合并到已有实现，删除死代码和调试残留。
4. 运行构建和测试确认没有回归。

## 报告

- **已清理**：`文件:行号` — 做了什么
- **建议后续处理**：需要更大改动或需要决策的技术债，每条附建议做法
