# /grill — 就这些改动考我

> 原文（Anthropic Claude Code 团队）："Grill me on these changes and don't make a PR until I pass your test."
> 中文：就这些改动来考我，我没通过你的考核之前不要提 PR。

## 做法

1. 查看当前改动（`git diff`、`git diff --staged`，以及相对主分支的改动）。用户若附带了参数，只看该范围。
2. 先自己吃透这些改动：改了什么、为什么改、影响到哪些调用方、有哪些边界情况和风险。
3. 向用户**逐个**提问，一次只问一个问题，等用户回答后再问下一个。问题要覆盖：
   - 这次改动的目的，以及为什么选择这种做法
   - 关键代码的行为（"这里传入空值 / 并发调用 / 失败重试时会怎样？"）
   - 受影响的其他模块、数据或接口
   - 如何验证它是正确的，测试是否覆盖到了
   - 回滚方式和潜在风险
4. 每个回答后给出简短评判：正确 / 部分正确 / 错误，并指出遗漏之处。答错的点稍后换个角度再考一次。
5. 考核中发现的真实问题（不只是用户答错，而是代码本身有问题）单独记下来。

## 结束

- 用户答对大部分关键问题、且没有未解决的代码问题时，宣布"通过"，然后询问是否现在提 PR。
- 否则宣布"未通过"，列出需要补的知识点和需要修的问题。**未通过前不要创建 PR。**
